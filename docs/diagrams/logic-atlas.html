1. Where things live

Three places, three jobs. Your folder is where you work and where your material already is. The base is the shared, versioned context. The plugin's own folder is per machine, never shared, and holds only what a seat has to remember.

2. What happens when a session opens

The session-start hook runs before your first message, every time. It asks one question at a time about the folder you opened, in this order, and stops at the first yes.

3. The link between your folder and the base

The base lives in its own drawer. The link is what makes it open on your desk. It is a record in the plugin's account file, never a line in any file of yours, and it carries an identity so a rename does not break it and a lookalike folder cannot borrow it.

4. When the setup offer appears

The desktop app shows nothing before your first message, so the offer is the first reply, whatever you typed. It repeats each session until you answer, then it stops.

5. The daily block

What the base does for you at the start of a session once it is active. The whole point of the product, in one figure.

6. What the safety check reads

Every command that names git or the GitHub tool passes through the check before it runs. A handful of things are refused everywhere. Content is read only where company context could leave.

7. Setting up a base, step by step

What "set up my company base" does, in the order it happens. Every step says what will happen before it happens, and nothing is written until you say yes to a whole document.

8. Confirmations and the stale rules

How the base knows a file is still true, and when it stops believing it. Identity is the address on the saved change, never a name typed into a file.
