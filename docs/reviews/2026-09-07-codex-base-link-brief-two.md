## The revised link design, which you are to attack
- The joined entry gains `content_root` (absolute path, realpath at registration) and `content_identity` (the folder's device number and inode number from os.stat, plus, when the content folder is itself a git repository, its canonical remote address with userinfo stripped, or null). Both are written by create_base at the moment the joined entry is appended, from the folder the person named at the location step. A base created with no named content folder has no link.
- Resolution order in session_start, all sources, before the offer branch: (a) cwd is a joined base or contains one as a `gtm-base` child, unchanged, wins over everything; (b) otherwise, if exactly one joined entry has `content_root` whose realpath equals cwd's realpath, the base is active; (c) otherwise, if exactly one joined entry has `content_identity` matching cwd's device and inode, the content folder was renamed or moved: rewrite `content_root` to cwd and the base is active; (d) if more than one entry matches in (b) or (c), print one fixed sentence naming both bases and activate nothing (fail closed); (e) otherwise, not a base: the offer rules as today.
- Registration refuses a content folder that is already the `content_root` or `content_identity` of another joined entry (one folder, one base); the person is told which base owns it and may pick a different folder or name none.
- A content folder that does not exist (unmounted drive, deleted) never invalidates the joined base; the entry is kept, the link simply does not fire. A recreated folder at the same path has a new inode, so (c) does not match; (b) matches by path only if the realpath is equal, which it would be. To close that hole, (b) also requires the device and inode to match; a path match with an identity mismatch is treated as "not the same folder" and reported by code, never activated. So activation always requires the identity.
- Activation by link means: the hook records the session, pulls the shared copy of the base (startup and resume only), injects the base's map and one question, and installs the git hook into the base, exactly as when cwd is the base. Skills resolve the base through the same resolver and operate on it by absolute path. Claude Code's own workspace, trust, and project settings are those of the folder the person opened; the plan states this plainly.
- What the link does not do: it never reads the content folder (the frozen consent list from setup is not extended by activation); it never writes into the content folder; it is not transported by the release-two remote (a second seat has no link unless they name a folder at their own join); the seat directory is still keyed by base id.
- The person can unlink or relink through the join skill by sentence ("this base belongs with the folder I am in"), which re-runs registration with the same refusals.
