## 1. Attack the design

**The link belongs in the product, but this specification is not ready to implement unchanged.** Verified below means code inspection; failure scenarios are inferred, not reproduced. No files were changed and no tests were run.

| Failure | Evidence and required correction |
|---|---|
| **Device and inode are not a lifetime identity.** | At [paths.py:318](/Users/brandonsellers/Build/gtm-base/plugins/gtm-base/lib/gtmbase/paths.py:318), both new activation branches would accept a deleted folder’s replacement if its device and inode are reused. I have not established that ordinary APFS deletion promptly reuses inode numbers, so I would not claim that as a reproduced APFS bug. The design nevertheless assumes non-reuse without establishing it. Add a creation discriminator where supported and explicitly define unsupported filesystems; do not substitute modification time or change time, which normal work changes. Apple documents birth time and a generation field, but its archived manual restricts generation access to the superuser. [Apple stat documentation](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/stat.2.html). |
| **Remounting can disable the link, and weakening the comparison can select another volume.** | Given a different device number after remount, neither (b) nor (c) matches. Never “repair” this by accepting inode alone. Persist a volume identifier where available, otherwise require explicit relinking after the mismatch. Apple exposes a persistent volume UUID, which can also be unavailable. This belongs in the identity helper used by [machine.py:330](/Users/brandonsellers/Build/gtm-base/plugins/gtm-base/lib/gtmbase/machine.py:330) and the resolver. [Apple volume UUID documentation](https://developer.apple.com/documentation/foundation/urlresourcevalues/volumeuuidstring). |
| **The remote currently contributes nothing to activation.** | Both branches compare only device and inode. Make a changed recorded remote a reason to require relinking, never a recovery key: two clones can share a remote. Without that check, a content subfolder inherits its parent repository’s remote. Define missing `origin`, removed remotes, and lookup failure separately. |
| **Path priority can defeat ambiguity detection.** | Suppose A has the current path and identity, while B has an old path and the same identity. Branch (b) activates A without reaching the collision in (c). Collect the complete identity-match set before selecting any link. The resolver checks cwd and direct children, not enclosing joined bases, so A’s interior can activate B. Refuse content roots equal to or inside any registered base or the seat directory, using resolved ancestry, and repeat that check on activation because folders move. Also refuse a link that an existing joined child would permanently shadow. |
| **Case aliases and symlinks need object semantics.** | Do not use lowercased path strings as identity or ancestry checks. Different case spellings should select the same object on a case-insensitive volume and remain distinct on a case-sensitive one. Registration through a symlink should bind its target; retargeting the symlink must not transfer ownership. Capture path and identity consistently, then revalidate before committing registration or recovery. Separate `realpath` and `stat` calls can otherwise record different targets during a change. The existing string comparisons at [machine.py:315](/Users/brandonsellers/Build/gtm-base/plugins/gtm-base/lib/gtmbase/machine.py:315) are insufficient for the new ownership checks. |
| **The current lock does not protect registration decisions.** | [machine.py:336](/Users/brandonsellers/Build/gtm-base/plugins/gtm-base/lib/gtmbase/machine.py:336) reads before [machine.py:264](/Users/brandonsellers/Build/gtm-base/plugins/gtm-base/lib/gtmbase/machine.py:264) takes the write lock. Lock the entire read, validate, mutate, write transaction; recovery must compare the old association before replacing it. |
| **A malformed or unavailable link must not erase a valid base.** | Extend [machine.py:32](/Users/brandonsellers/Build/gtm-base/plugins/gtm-base/lib/gtmbase/machine.py:32), [machine.py:143](/Users/brandonsellers/Build/gtm-base/plugins/gtm-base/lib/gtmbase/machine.py:143), and [machine.py:255](/Users/brandonsellers/Build/gtm-base/plugins/gtm-base/lib/gtmbase/machine.py:255). ## 2. Release verdict

**I now agree with building the link in this release, subject to closing these gaps.** Opening the company folder is the required product behavior, so deferral would knowingly omit the product’s main job. That supports shipping a bounded association with explicit recovery, not treating device and inode as conclusive lifetime identity.

## 3. Smallest ordered implementation and tests

1. **Define one identity and ownership contract.** Specify volume identity, creation discrimination, remote-change behavior, supported filesystems, and explicit relinking when evidence is insufficient. Test identity reuse with injected metadata, remount changes, same-remote clones, case variants, symlink retargeting, and moves into protected directories.

2. **Make registry mutations transactional.** Extend schema validation and preservation, then implement register, unlink, relink, and compare-before-rewrite under one lock. Test legacy rows, malformed links, unavailable bases/content, concurrent registrations, and unlink racing with recovery.

3. **Carry the named folder through central creation.** Change proposal and creation guards, preserve the explicit content choice through setup, and return recoverable post-rename failures. Test repository/sync ancestors, redirected parents, unknown sync coverage, no named folder, collision refusal, and interrupted registration.

4. **Implement one read-only resolver for hooks and skills.** Set physical and renamed-base precedence explicitly, count all ownership matches, validate the selected base, and return recovery information without writing. Test mixed path/identity collisions, physical-base precedence, copied and relocated bases, identity mismatch, and explicit repair with no active base.

5. **Integrate the hook with a deadline and usable diagnostics.** Persist recovery only in the writing half; preserve existing startup/resume behavior and all-source session recording. Test both halves concurrently, slow Git, lock contention, inaccessible storage, and recovery output reaching the assistant without a map from either conflicting base.

6. **Run the actual return-session acceptance test.** Open the company folder, receive the correct map and question, use a skill against the external base, rename the company folder, return again, then unlink and relink. Verify content files remain untouched, consent remains frozen, and the association stays account-local.
